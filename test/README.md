# E2e с PostgreSQL

Требования: Node.js 22.12+ (нативный require ESM), pnpm, Docker Compose v2 с поддержкой `--wait`.

Из корня backend:

```sh
docker compose -p pet-e2e -f docker-compose.test.yml up -d --wait
pnpm run test:e2e
```

Команда тестов сначала собирает приложение, затем запускает Jest.
Тестовый сервер использует настоящие AppModule, ConfigModule, TypeORM,
Passport и configureApp. Отдельный Node-процесс позволяет загрузить ESM-пакет
@nestjs/config без мока в текущем CommonJS-наборе Jest.

Сервер получает фиксированную тестовую конфигурацию и пустую временную рабочую
директорию: проектный `.env` не читается, переменные родительского окружения не
наследуются. HTTP-порт выбирается ОС и слушает только 127.0.0.1.

Единственное разрешённое подключение: 127.0.0.1:5434, БД pet_test,
пользователь pet_test. Параметры проверяются до импорта AppModule и запуска
synchronize; затем проверяются current_database() и current_user.
Схема пока создаётся через synchronize, как в локальном приложении.
После этапа миграций тестовый запуск тоже должен применять миграции.

Тесты создают пользователей с уникальными случайными email и удаляют только
свои записи. Общего TRUNCATE, DROP DATABASE или очистки рабочей БД нет.
Повторный запуск не требует пересоздания контейнера.

Проверки: register → login → me, сохранение bcrypt-хеша, точный состав
безопасного профиля и ответа login, неверный пароль, дубликат email,
недопустимое поле role, отсутствие/некорректный JWT, отказ при небезопасных
параметрах БД. Гонку параллельных регистраций этот набор не проверяет.

Остановка тестового контейнера:

```sh
docker compose -p pet-e2e -f docker-compose.test.yml down
```

Данные тестовой PostgreSQL находятся в tmpfs и теряются при остановке контейнера.
